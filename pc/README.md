# Мост для ПК

ПК-часть: локальная модель (llama.cpp) доступна телефону по Wi-Fi Direct, без роутера.

```
Телефон ──Wi-Fi Direct──▶ llm-bridge (192.168.49.1:8765, токен) ──▶ llama-server (127.0.0.1:8080)
                                  │
                                  └── чаты: data/chats.db
```

ПК — центр системы: чаты и все ветки хранятся здесь, ответы генерируются как задачи
на ПК и не обрываются, если телефон отключился. После переподключения телефон
догружает пропущенное.

## Установка

```bash
./pc/install.sh
```

Ставит зависимости (PyQt6, aiohttp, qrcode), привилегированный helper
`/usr/local/sbin/llm-bridge-helper` (адрес, DHCP, обход VPN) с запуском через `sudo`
без пароля и добавляет пользователя в группу `netdev` (после этого — перезагрузка).

## Запуск

```bash
./run.sh              # окно
./run.sh --minimized  # сразу в трей
./run.sh --headless   # без окна: модель и канал включаются сразу, лог в консоль
```

В окне:
- **Запустить модель** / **Включить канал**; галочки — что делать при старте.
- **Запускать при входе в систему** — создаёт `~/.config/autostart/llm-bridge.desktop`,
  приложение стартует свёрнутым в трей.
- Крестик окна прячет его в трей; выход — через меню значка.

## Wi-Fi Direct

Имя сети и пароль группы постоянные (`p2p_ssid`, `p2p_psk` в конфиге, создаются один раз),
поэтому телефон сопрягается один раз и после перезагрузки ПК подключается сам.
Если wpa_supplicant не примет постоянную группу, создастся случайная — это будет в логе.

`p2p_freq` в конфиге: `2` — 2,4 ГГц, `5` — 5 ГГц, либо точная частота в МГц.

Конфиг: `data/config.json`. Изменения — после перезапуска.

## API (версия 2)

Все запросы, кроме `/api/ping`, — с заголовком `Authorization: Bearer <token>`.

| Метод | Путь | |
|---|---|---|
| GET | `/api/ping` | `{"app","api","name"}` |
| GET | `/api/status` | модель, `n_ctx`, vision, занятость |
| GET/POST | `/api/chats` | список / создать `{title?, system_prompt?, settings?}` |
| GET/PATCH/DELETE | `/api/chats/{id}` | чат с активной веткой / изменить (`make_default`) / удалить |
| POST | `/api/chats/{id}/messages` | `{content, replace_id?}` — отправить и начать ответ |
| POST | `/api/chats/{id}/cancel` | остановить генерацию |
| PATCH/DELETE | `/api/messages/{id}` | правка на месте / удаление с продолжениями |
| POST | `/api/messages/{id}/regenerate` | новый вариант ответа |
| POST | `/api/messages/{id}/select` | переключиться на вариант/ветку |
| GET/PUT | `/api/settings` | промпт и параметры по умолчанию |
| GET | `/api/ws` | WebSocket событий |
| GET/POST | `/v1/models`, `/v1/chat/completions` | прокси к llama-server |

События WebSocket: `hello`, `status`, `busy`, `chat.updated`, `chat.deleted`, `chat.changed`,
`message.added`, `message.delta` (смещения `offset`/`r_offset` в единицах UTF-16),
`message.done`, `message.updated`.

`settings` чата — параметры генерации llama-server: `temperature`, `top_p`, `top_k`, `min_p`,
`repeat_penalty`, `dry_multiplier`, `xtc_probability`, `max_tokens` и др.

## Память и контекст (этап 1)

Контекст ответа собирается слоями: системный промпт → память (факты) → хроника →
закреплённые сообщения → последние сообщения дословно, сколько поместится.

- **Факты** модель извлекает в фоне после каждых 4 новых сообщений (пока простаивает;
  новый вопрос пользователя прерывает это и выполняется первым). Закреплённые и
  исправленные вручную факты модель не меняет.
- **Хроника** дописывается перед ответом, когда старые сообщения перестают помещаться;
  с запасом, чтобы не пересчитываться на каждом шаге. Хроника привязана к ветке.
- **Закреплённое сообщение** остаётся в контексте, даже выпав из окна.
- **Параметры**: если в чате не заданы — рекомендуемые для Qwen3
  (без размышлений: t=0.7, top_p=0.8, top_k=20, presence_penalty=1.0, до 1536 токенов;
  с размышлениями: t=0.6, top_p=0.95, до 4096 токенов). Предел длины есть всегда.
  `thinking` в параметрах чата — размышления (по умолчанию выключены).

Новые запросы API: `POST /api/messages/{id}/continue`, `PATCH /api/messages/{id}` `{pinned}`,
`GET /api/chats/{id}/memory`, `POST /api/chats/{id}/facts`, `PATCH|DELETE /api/facts/{id}`,
`PUT /api/chats/{id}/chronicle`, `POST /api/chats/{id}/memory/refresh`.
События: `message.stage`, `memory.updated`.

## Фото

`POST /api/chats/{id}/messages` принимает `images: [base64 JPEG/PNG]` (до 6). Файлы хранятся в
`data/images/`, отдаются через `GET /api/images/{имя}`. Модели картинки
передаются в формате OpenAI (`image_url`), нужна модель с mmproj. Картинка учитывается в бюджете
контекста (оценка: 1 токен на 32×32 пикселя).

## Генерация изображений (этап 4)

Рисует stable-diffusion.cpp (`sd-server`), который мост запускает сам. Видеокарта одна, поэтому:
перед рисованием мост выгружает llama-server и загружает модель изображений, а при следующем
текстовом сообщении — наоборот. Серия картинок подряд перезагрузок не вызывает.

Подготовка (сборка с CUDA и загрузка Krea 2 Turbo; `--qwen` — ещё Qwen-Image 2.1):

```bash
./scripts/setup-images.sh
```

Профили — `data/image_profiles.json` (кнопка «Профили изображений»):
файлы моделей (шаблоны с `*`, поиск во вложенных папках без учёта регистра), доп. флаги
`sd-server`, размер, шаги, cfg, сэмплер, негативный промпт, стиль (добавляется к запросу).

API: `GET /api/image/profiles`, `POST /api/chats/{id}/images {prompt, profile?, width?, height?,
steps?, cfg?, seed?, negative?}`. Ответ модели в чате становится картинкой; прогресс —
событиями `message.stage` (`unloading_llm`, `loading_image_model`, `image` с `done/total`,
`loading_llm`). Статус `llama: "swapped"` — модель выгружена на время рисования.

## Папки моделей

```

models/image     модели изображений: диффузия, текстовые энкодеры, VAE (setup-images.sh)
models/lora      LoRA для sd-server (--lora-model-dir)
models/upscale   апскейлеры (--hires-upscalers-dir)

```

Папка `models/` лежит в корне проекта и в git не попадает. mmproj (зрение)
подбирается к выбранной модели сам — по самому похожему имени в той же папке.

## Рисование в диалоге (шаг 1)

Текстовая модель получает инструмент `draw_image` (нужен `--jinja`, мост добавляет его сам) и
рисует к своему ответу: сначала текст, затем картинка под ним. Промпт для модели изображений
она пишет сама — по-английски и подробно, с внешностью персонажей из описания чата и фактов.

Настройка чата `illustrate`: `off` — только кнопка «Нарисовать…», `on_request` (по умолчанию) —
когда попросят в сообщении, `auto` — ещё и сама иллюстрирует ключевые моменты.

Модель видит, что нарисовала: две последние картинки — пикселями (если у модели есть mmproj),
более старые — по подписи, которую она сама делает в фоне по пикселям (`meta.drawn.seen`).

Сообщение с рисунком модели: `meta.drawn = {source: "model", prompt, negative, caption,
orientation, profile, seed, width, height, steps, seen?}`, ошибка рисования — `meta.draw_error`
(текст ответа при этом цел). Ручное рисование: `meta.kind = "image"`, `source: "user"`,
`request` — исходный запрос, если промпт доработала модель.

| Метод | Путь | |
|---|---|---|
| POST | `/api/chats/{id}/images` | `{…, enhance: true}` — модель доработает запрос перед рисованием |
| POST | `/api/image/enhance` | `{text, chat_id?}` → `{prompt, negative}` |
| POST | `/api/messages/{id}/redraw` | перерисовать картинку сообщения на месте (новый seed) |

Этапы `message.stage`: `drawing` (модель вызвала инструмент), `enhancing` (пишет промпт),
затем обычные этапы рисования.

## Персонажи и персоны (шаг 2, часть 1)

Карточки хранятся на ПК (таблица `cards`): `character` — персонаж, которого играет модель,
`persona` — каким пользователь предстаёт в ролевых чатах. Поля описаны в `cards.py`; самое важное —
`appearance_tags`: английские теги внешности, из которых собираются промпты рисования, чтобы
персонаж выглядел одинаково на портрете и на всех иллюстрациях.

Карточку не нужно заполнять руками: описание своими словами → `POST /api/cards/generate`, модель
заполнит все поля; любое поле можно переписать моделью с пожеланием (`/rewrite`).

Чат с персонажем (`POST /api/cards/{id}/chat`) хранит в настройках `character_id`/`persona_id`;
роль собирается в системный промпт при каждой генерации, так что правки карточки сразу действуют
во всех её чатах. Первое сообщение — приветствие персонажа, с портретом (модель его видит).

Удаление чатов с телефона работает и без связи: чат пропадает сразу, на ПК удаляется при
следующем подключении. Список чатов кэшируется на телефоне.

## Миры, сцены, квест и история (шаг 2, часть 2)

**Мир** (`kind: world`): описание, тон, стиль картинок (`style_tags`) и лорбук — таблица `lore`.
Запись лорбука попадает в системный промпт, когда её ключи (основы слов) встречаются в последних
сообщениях, или всегда (`always`). Мир по описанию своими словами создаётся сразу с лорбуком;
`POST /api/cards/{id}/lore/generate {text}` — модель дописывает записи по просьбе.

**Сцена** (`POST /api/scenes`): чат с настройками `mode` (`chat` | `quest` | `story`),
`character_ids`, `persona_id`, `world_id`. Завязка уходит первым сообщением (`meta.kind =
"directive"`), и модель сразу пишет начало. Несколько персонажей: модель ведёт всех, реплики
начинаются с «**Имя:**», ответ помечается `meta.speakers`; `reply_as` в отправке — кто отвечает.

**Квест**: после хода ведущего отдельный запрос со схемой JSON обновляет состояние
(`meta.state`: где, время, здоровье, инвентарь, цели, отношения, заметки) и варианты действий
(`meta.choices`). Состояние хранится в ходе — поэтому следует веткам. Правка вручную —
`PATCH /api/messages/{id}/state`.

**История**: модель — соавтор; команды «Продолжи», «Поворот» — служебные сообщения,
«Перепиши / Подробнее / Короче» — новый вариант ответа с пожеланием
(`POST /api/messages/{id}/regenerate {wish}`), он доступен и в любом чате.

## Фоновая модель и режим «Чат» (отношения)

**Фоновая модель** — маленькая LLM на процессоре (`./scripts/setup-helper.sh`, по умолчанию
Qwen3-4B-Instruct-2507 Q4_K_M в `models/llm/helper/`). Мост запускает её сам вторым
llama-server на порту `bg_port` (8081). На ней: факты памяти, отношения, состояние квеста,
оценка подарков — большая модель занята только ответами, а фон не мешает рисованию.
Без неё всё это делает большая модель, как раньше.

**Чувство времени**: в чате модель знает текущее время ПК и сколько вы молчали.
Меняющиеся данные (время, отношения, состояние квеста) кладутся в последнее сообщение
пользователя, а не в системное — начало контекста не меняется, и llama-server не пересчитывает его.

**Отношения** персонажа с персоной (таблица `relations`, общие для всех их чатов): симпатия
−100…100, доверие 0…100, статус (незнакомец / знакомый / друг / близкий / неприязнь / враг),
настроение (через 8 ч возвращается к обычному), события и обещания. После каждого ответа
фоновая модель оценивает изменения; подсказка («Мире понравилось…») — в `meta.events` ответа.
Персонаж ведёт себя по отношениям: может отказать в фото, откровенности, встрече; тайну
(поле карточки `secret`) открывает при доверии от 60.

Стиль чата `chat_style`: `messenger` — переписка (короткие сообщения через пустую строку,
на телефоне — отдельными пузырями), `roleplay` — рядом, с действиями.

«Пишет первым»: телефон при открытии чата вызывает `POST /api/chats/{id}/nudge`; если тишина
дольше 3 ч, персонаж с шансом по симпатии пишет первым (один бросок на паузу; `initiative`).

**Монеты и подарки**: кошелёк персоны (старт 100), квест начисляет `coins_delta`
по ходу игры; `POST /api/chats/{id}/gift {text}` — цену назначает модель, реакция — по вкусам.

**Я ведущий** (`mode: gm`): вы мастер, модель играет героев; «[Помощник ведущего] …» — ответ
вне игры с идеями для мастера. Состояние игры ведётся так же, как в квесте.

## Визуальная новелла (режим «История»)

Модель пишет историю в разметке: «[Место: …]» — смена места, «**Имя** (эмоция): текст» —
реплика, остальное — повествование. После ответа текст разбирается на кадры (`meta.beats`);
для нового места фоновая модель пишет английский промпт, и фон рисуется один раз
(`GET /api/chats/{id}/vn`, события `vn.background`). Эмоции персонажа — шесть спрайтов
(`POST /api/cards/{id}/sprites`, сид портрета — лицо похожее). На телефоне «📖 Новелла»:
фон, спрайт говорящего, имя, текст по нажатию; в конце — свой ход или «Продолжи» / «Поворот».

## MOSS-Image

Поддержка есть в stable-diffusion.cpp (master-975+). `./scripts/setup-images.sh --moss` обновит
и пересоберёт sd.cpp и скачает: MOSS-Image-SFT UD-Q4_K_XL (unsloth), текстовый энкодер
Qwen3.5-9B Q4_K_M, VAE и tokenizer.json из unsloth/MOSS-Image-SFT-FP8. Профиль «MOSS-Image SFT»
(50 шагов, CFG 3) сам добавится в image_profiles.json. Силён в тексте на картинке и раскладке;
медленнее Krea 2 Turbo.

## Похожие лица и поза по фото (шаг 3)

Профили изображений получили роли: `generate`, `edit` (рисует по образцам — Qwen-Image 2.1
с файлом зрения mmproj-Qwen3VL-8B, `optional_files.llm_vision`), `text` (MOSS-Image).
Образцы передаются sd-server в `ref_images` (до 3, base64).

- Модель в чате указывает в `draw_image`, кто из персонажей в кадре (`characters`) — их
  портреты идут образцами, и лица получаются те же; `pose_from_photo` — присланное фото идёт
  образцом позы и кадра; `purpose=text` — картинку рисует профиль с ролью `text`.
- Ручное рисование: упомянутые в запросе персонажи — по портретам (`likeness: false` — выкл).
- Эмоции для новеллы — по образцу портрета.
- Настройка чата `likeness` (по умолчанию вкл).

## Деньги, свидания, «что было»

- `POST /api/chats/{id}/money {action: borrow|repay}` — занять: персонаж решает сам
  (фоновая модель видит его ответ, `money_given`); долг хранится в отношениях и виден персонажу.
- `POST /api/chats/{id}/date` — свидание: история-новелла с этим персонажем, отношения меняются
  по ходу; `/date/finish` — итог вечера в события отношений.
- Персонаж знает, с кем ещё вы общаетесь (статусы), и поле карточки «Знакомства».
- `GET /api/chats/{id}/recap` — «в предыдущих сериях».

## Персонаж меняется; развилки, галерея, кадр

- После обновления памяти чата фоновая модель проверяет, не случилось ли с персонажем что-то
  надолго, и предлагает правку поля карточки (`GET /api/proposals`, событие `card.proposal`);
  принять или отклонить — `POST /api/proposals/{id} {accept}`.
- История: строки «[Выбор: …]» в конце ответа → `meta.choices`; выбранный вариант уходит
  сообщением с `choice: true`. `GET /api/chats/{id}/choices` — карта выборов (выбрано / пробовали
  в других ветках). «[Кадр: …]» — указание развернуть строку в сцену.
- `GET /api/chats/{id}/gallery` — все картинки чата; настройка `vn_bg: manual` и
  `POST /api/chats/{id}/vn/background {name}` — фоны по кнопке.

## Единый стиль картинок
У персонажа есть поле «Стиль картинок» (`art_style`), у мира — `style_tags`. Стиль мира важнее стиля
персонажа; если оба пусты — фотореализм. Этот стиль добавляется к портрету, спрайтам, картинкам в чате
(и от модели, и ручным) и фонам новеллы, поэтому всё выглядит одинаково.

## Какая модель что рисует
Задачи: портрет персонажа, картинки в чате, картинки с лицом персонажа (по образцу портрета или
позы), эмоции для новеллы, фоны новеллы, надписи. Для каждой мост берёт первую готовую модель из
своего списка предпочтений («Авто»); с телефона (меню → «Модели картинок») модель можно закрепить.
Если модель не загрузилась или упала — рисует следующая подходящая, в логе об этом строка.

| Задача | «Авто» по порядку |
| --- | --- |
| Портрет | MOSS → Qwen-Image → Krea Turbo |
| Картинки в чате | MOSS → Krea Turbo → Qwen-Image |
| С лицом персонажа | Qwen-Image → Qwen-Image Turbo |
| Эмоции | Qwen-Image (по портрету), иначе как портрет |
| Фоны новеллы | Krea Turbo → Qwen-Image Turbo → MOSS |
| Надписи | MOSS → Qwen-Image |

Параметры моделей взяты из документации stable-diffusion.cpp: Krea 2 Turbo — 8 шагов, CFG 1;
Qwen-Image 2.1 — 20 шагов, CFG 6, размеры кратны 32; MOSS-Image SFT — 50 шагов, CFG 3, кратно 16.
Качество «быстрее / обычное / выше» меняет шаги (×0.7 / ×1 / ×1.3) и размер (выше — на четверть);
у turbo-моделей шаги фиксированы. Всё это лежит в `data/image_profiles.json`.

--qwen-turbo`. После загрузки её можно закрепить за задачей «С лицом персонажа».

## Несовершеннолетние персонажи
Если в карточке персонажа или персоны указан возраст меньше 18, в сцену добавляется ограничение:
без романтики и флирта в тексте и картинках; «Свидание» для такого персонажа недоступно.
